# Служебный портал Альянса «Ценность каждого»

Закрытая платформа для членов Альянса: голосования, взносы, мероприятия, рабочие группы, карта и контакты сообщества.
Архитектура и схема БД — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

| Каталог | Что внутри |
|---|---|
| `backend/` | API на NestJS + Prisma + PostgreSQL. Swagger: `/api/docs` |
| `frontend/` | React + TypeScript + Mantine (Vite) |
| `scripts/` | бэкап и восстановление |
| `docs/` | архитектура, схема БД |

## Статус этапов

- [x] **Этап 2.** Голосования (открытые, поимённые; 1 организация = 1 голос), 4 формата вопросов, кворум, напоминания,
  автозакрытие по сроку, итоговый протокол PDF, выгрузка CSV, приём кандидатов по итогам голосования
- [x] **Этап 3.** Взносы: настройки по годам, начисление, платежи, статусы, документы, договоры пожертвования,
  сводка для секретаря, напоминания должникам, связь с правом голоса
- [x] **Этап 4.** Мероприятия: календарь, регистрация (очно/онлайн), напоминания, .ics, отметка присутствия,
  протоколы с повесткой, решениями и ссылками на голосования (PDF, приложения), посещаемость и рейтинг активности
- [x] **Этап 5.** Рабочие группы: участники и руководители, план работы, задачи с исполнителями и сроками,
  обсуждения, архив документов, протоколы заседаний, активность групп на главной
- [x] **Этап 6.** Карта Альянса (89 регионов, слои «члены / кандидаты / партнёры», организации региона)
  и справочник контактов с фильтрами и настройками приватности
- [x] **Этап 7.** Уведомления (колокольчик, лента, настройки «в портале / по почте»), настройки портала
  (кворум и напоминания по умолчанию), редактор шаблонов писем с предпросмотром, рейтинг активности на главной

## Локальный запуск (Windows, без Docker)

Нужен только Node.js 22. PostgreSQL ставится как npm-пакет.

```bash
cd backend
npm install
copy .env.example .env
npm run db:start
npx prisma migrate deploy
npm run seed
npm run start:dev
```

В отдельном терминале:

```bash
cd frontend
npm install
npm run dev
```

Портал: http://localhost:5173 · API: http://localhost:3000/api · Swagger: http://localhost:3000/api/docs

> PostgreSQL на Windows не работает с кириллицей в пути. Скрипт `npm run db:start` сам создаёт ASCII-ссылку
> `D:\alliance-portal` → папка проекта (junction, без прав администратора) и запускает сервер через неё.
> Другой путь можно задать переменной `DEV_ASCII_ROOT`. Остановить БД: `npm run db:stop`.

## Голосования: как это работает

- Создают голосования администратор и секретарь. Черновик можно править и прикладывать к нему документы.
  После публикации вопросы, документы и состав участников фиксируются.
- Участники: все члены Альянса, выбранные члены или члены с оплаченным взносом за текущий год
  (последнее заработает после этапа 3, когда появятся взносы).
- Голосует учётная запись организации. До окончания голос можно изменить, каждое изменение записывается в аудит.
- Итоги видны всем участникам в реальном времени, поимённо. Кандидат не видит голосование по своей кандидатуре,
  пока оно не завершено.
- Раз в минуту API закрывает голосования с истёкшим сроком, формирует PDF-протокол и рассылает напоминания
  не проголосовавшим (за выбранное число часов до окончания).
- Правила подсчёта:
  - кворум — доля проголосовавших организаций;
  - «за/против/воздержался» — решение принято, если «за» больше половины проголосовавших;
  - один вариант — побеждает вариант с наибольшим числом голосов;
  - рейтинг — метод Борда.

## Взносы: как это работает

- Секретарь задаёт для каждого года сумму, срок оплаты и льготный период, затем нажимает «Начислить».
  Взнос начисляется всем членам Альянса. Новому члену Альянса взнос текущего года начисляется сам при смене статуса.
- Платежи отмечает секретарь (сумму, дату, номер платёжки). Статус пересчитывается автоматически:
  - «оплачен», если оплачено не меньше начисленного;
  - «частично», если оплачена часть, а срок ещё не прошёл;
  - «не оплачен», если оплат нет, а срок ещё не прошёл;
  - «просрочен», если срок и льготные дни прошли, а оплачено меньше начисленного.
  «Освобождён» — ручное решение секретаря с примечанием.
- Организация видит свои взносы за все годы и договоры пожертвования. К своему взносу она может приложить
  платёжное поручение, к своему договору — подписанный скан.
- Напоминания должникам приходят автоматически: за 30 и за 7 дней до срока, затем в первый день просрочки
  и далее раз в 14 дней. Секретарь может разослать их вручную, но не чаще раза в день.
  Письмо получают пользователи организации и её сотрудники с областью ответственности «Взносы и договоры».
- Переключатель «голосуют только оплатившие» в настройках года действует на новые голосования «все члены Альянса».

## Мероприятия и протоколы: как это работает

- Секретарь создаёт мероприятие (общее собрание, конференция, заседание РГ, иное), формат — очно, онлайн или смешанный.
  Приглашения получают пользователи организаций-членов, на заседание РГ — участники группы. Партнёры видят только
  мероприятия с отметкой «видно партнёрам».
- Участник отвечает «буду очно», «буду онлайн» или «не смогу» до срока регистрации (по умолчанию — до начала).
  За сутки до начала подтвердившим приходит напоминание. Событие можно добавить в свой календарь файлом .ics.
- После начала секретарь отмечает присутствие; первая отметка переводит мероприятие в «состоялось».
  При отмене подтвердившие получают уведомление.
- Протокол создаётся из карточки мероприятия, пункты повестки подставляются из описания. Каждый пункт: вопрос,
  «слушали», «решили», ссылка на голосование (в протоколе выводится его итог). Черновик видят секретарь и руководитель РГ;
  после публикации — все члены Альянса, участники получают уведомление. Протокол выгружается в PDF.
- Посещаемость считается по организациям. Рейтинг активности — среднее из доли посещённых мероприятий
  и доли голосований, в которых организация участвовала.

## Рабочие группы: как это работает

- Группы создаёт администратор и назначает руководителя. Представители организаций-членов могут вступить в группу
  сами или их добавляет руководитель; руководитель получает уведомление о новом участнике.
- Обзор группы и план работы видят все члены Альянса. Задачи, обсуждения и документы — участники группы
  и пользователи с правом «видеть всё».
- План ведёт руководитель; ответственный за пункт может менять его статус. Выполнение плана — доля выполненных пунктов
  без учёта отменённых.
- Задачи: руководитель поручает любому участнику, участник может завести задачу себе. Исполнитель и автор меняют статус
  и описание, остальное — руководитель. Исполнитель получает уведомление о поручении и о новых комментариях.
  Задача просрочена, если не выполнена, а день срока (по Москве) прошёл.
- Протоколы заседаний группы ведёт её руководитель (черновик → публикация), так же как секретарь — общие протоколы.

## Карта и контакты

- Карта — плиточная: каждый из 89 субъектов — квадрат примерно на своём месте (запад слева, север сверху),
  без внешних геоданных. Цвет — число организаций выбранного слоя. Раскладка — `frontend/src/pages/map/grid.ts`.
- Карту видят все участники портала, включая кандидатов и партнёров. Контакты организаций в карточке региона —
  только членам Альянса. Организация может скрыть себя с карты (флажок в профиле).
- Справочник «Контакты» (только для членов Альянса): организации и сотрудники с областями ответственности,
  фильтры по федеральному округу, региону, области ответственности и рабочей группе.
- Приватность: организация может скрыть email и телефон; сотрудник — email, телефон или убрать себя из справочника.
  Скрытое видят только своя организация, администратор и секретарь.

## Уведомления и настройки

- Колокольчик в шапке показывает непрочитанные; лента и настройки — «Уведомления» в меню профиля.
  Для каждого типа события можно отключить уведомление в портале и/или письмо. Письма о входе,
  приглашениях и сбросе пароля отключить нельзя.
- «Администрирование → Настройки» (только администратор): кворум и напоминания по умолчанию для новых голосований,
  дни напоминаний о взносах; шаблоны писем с переменными вида {{fullName}} — значения экранируются, предпросмотр
  открывается в изолированном фрейме. Изменения пишутся в журнал аудита.

## Демо-стенд (Render, бесплатно)

Один контейнер (корневой `Dockerfile`): API отдаёт и собранный фронтенд. Конфигурация — `render.yaml`
(веб-сервис + бесплатная PostgreSQL Render; база живёт 30 дней, потом её нужно пересоздать).

1. На [render.com](https://render.com) войдите через GitHub → **New → Blueprint** → выберите репозиторий → **Apply**.
   Render сам создаст базу и сервис. Первая сборка — 5–10 минут.
2. Откройте адрес вида `https://alliance-portal-demo.onrender.com` и войдите демо-учётками (см. выше),
   пароль `Alliance2026!`. На стенде включены `DEMO_DATA=true` (демо-данные в пустую БД) и `DISABLE_2FA=true`
   (вход без второго фактора, в том числе для администратора и секретаря).

Ограничения бесплатного плана: после 15 минут без посетителей сервис засыпает, первое открытие — около минуты;
загруженные файлы стираются при перезапуске; письма не отправляются (SMTP не настроен).
Демо-пароли известны всем, у кого есть ссылка, — не вносите на стенд реальные данные.

**Никогда не включайте `DISABLE_2FA` и `DEMO_DATA` в рабочей установке.**

## Реальные данные рядом с демо-записями

Демо-голосования, мероприятия и рабочие группы помечены `is_demo`, показываются с пометкой «ДЕМО» и не входят в карту, справочник, кворум,
взносы и статистику. Данные из таблицы загружаются скриптом; CSV-файлы хранятся вне репозитория.

1. Выгрузите листы таблицы в папку: `members.csv`, `partners.csv`, `board.csv`, `candidates.csv`,
   `applicants.csv`, `rejected.csv`, `groups.csv`.
2. Уберите демо-организации и демо-людей (голосования останутся, учётка администратора получит новый пароль):
   `npx ts-node --transpile-only prisma/remove-demo.ts`.
3. Проверьте разбор: `npx ts-node --transpile-only prisma/import-alliance.ts <папка>`.
4. Загрузите данные: та же команда с `--apply`. Повторный запуск уже загруженное не меняет.
5. Назначьте администратора: `npx ts-node --transpile-only prisma/make-admin.ts <email> "<ФИО>" "<часть названия организации>"`.
6. Внесите правление с листа «Правление»: `npx ts-node --transpile-only prisma/setup-board.ts <папка>`.
   Скрипты выводят личные ссылки-приглашения, их передают вручную.

Телефоны, почта и мессенджеры загружаются скрытыми от других членов Альянса; их открывают после согласия человека.

## Продакшен (docker compose)

```bash
cp .env.production.example .env
docker compose up -d --build
```

Перед запуском заполните секреты в `.env` и `BOOTSTRAP_ADMIN_EMAIL`. При первом запуске в пустую БД в логе контейнера
`api` (`docker compose logs api`) появится ссылка-приглашение первого администратора. Приложение слушает порт `HTTP_PORT`
(по умолчанию 8080). Перед ним поставьте HTTPS-прокси; `COOKIE_SECURE=true` требует HTTPS.

Бэкапы: `scripts/backup.sh` (pg_dump + архив файлов, хранение 14 дней, пример cron внутри).
Восстановление: `scripts/restore.sh`.

## Безопасность (этап 1)

- Пароли — argon2id. Вход ограничен по частоте; после 5 неудачных попыток вход блокируется на 15 минут.
- Access-токен (15 мин) хранится только в памяти браузера. Refresh-токен — httpOnly + SameSite=Strict cookie с ротацией;
  при повторном использовании старого токена отзывается вся цепочка сессий.
- CSRF: cookie-эндпоинты требуют заголовок `X-CSRF`.
- 2FA (TOTP) обязательна для администратора и секретаря. Секреты зашифрованы AES-256-GCM.
- Блокировка пользователя и смена ролей действуют сразу: права пересчитываются на каждом запросе.
- Журнал аудита только для добавления: UPDATE и DELETE запрещены триггером БД. Пароли и секреты в журнал не попадают.
- Реквизиты организаций видны только самой организации и пользователям с правом «видеть всё»; контакты — только членам Альянса.
